# Team CalTalk 도메인 정의서

버전 0.4 · 최종 수정일 2026-09-30

## 1. 개요

Team CalTalk은 팀 단위로 일정을 관리하는 캘린더와 채팅을 한 화면에 합친 애플리케이션이다. 팀 일정을 한곳에 모으고, 일정 변경과 관련 대화를 같은 곳에서 처리한다.

## 2. 문제 정의

| ID | 문제 | 해결 방향 |
|----|------|-----------|
| P-01 | 팀 일정이 개인 캘린더, 메신저, 엑셀 등에 흩어져 있어 일정이 충돌하거나 빠진다 | 팀 캘린더 하나로 일정을 모으고 팀 구성원 모두에게 공유한다. 충돌 자동 감지는 범위 밖이며, 공유된 캘린더로 충돌을 인지한다 |
| P-02 | 일정과 대화가 따로 있어 변경된 맥락을 추적하기 어렵다 | 캘린더와 채팅을 한 화면에 두고, 채팅 이력을 일자별로 저장한다 |
| P-03 | 팀장이 팀원의 일정을 직접 관리하기 어렵다 | 팀 일정의 추가·수정·삭제 권한을 팀장에게만 준다 |

## 4. 핵심 도메인 개념 (용어집)

| 용어 | 정의 |
|------|------|
| 사용자 (User) | 이메일과 비밀번호로 회원가입하고 로그인해서 서비스를 이용하는 사람. 여러 팀에 속할 수 있으며, 팀마다 팀장이나 팀원 역할을 가진다 |
| 팀 (Team) | 일정과 채팅을 함께 쓰는 사용자 그룹 |
| 팀 구성원 | 팀에 속한 사용자 전체(팀장과 팀원) |
| 팀장 (Team Leader) | 팀을 만든 사용자. 팀마다 1명이며, 팀 일정을 추가·수정·삭제할 권한이 있다 |
| 팀원 (Team Member) | 초대 코드로 팀에 참여한 구성원. 팀 일정은 조회만 할 수 있으며, 채팅과 본인 관련 일정의 변경 요청은 할 수 있다 |
| 초대 코드 (Invite Code) | 팀을 만들 때 생성되는 팀마다 유일한 코드. 팀장만 확인할 수 있으며, 팀원은 이 코드로 팀에 참여한다 |
| 팀 일정 (Schedule) | 팀에 속한 일정. 제목, 시작·종료 일시, 관련 팀원을 가진다 |
| 관련 팀원 (Participant) | 특정 일정에 연관된 팀원. 같은 팀의 팀원 역할 구성원 중에서만 지정하며, 팀장은 관련 팀원이 될 수 없다. 이 팀원만 해당 일정의 변경을 요청할 수 있다 |
| 캘린더 뷰 (Calendar View) | 팀 일정을 월·주·일 단위로 보여 주는 화면 |
| 채팅방 (Chat Room) | 팀 구성원(팀장·팀원)이 대화하는 공간. 캘린더와 같은 화면에 표시된다 |
| 메시지 (Message) | 채팅방에 작성한 글. 작성자, 작성 일시, 내용을 가진다 |
| 탈퇴한 사용자 | 탈퇴한 사용자가 쓴 메시지의 작성자 표시. 메시지 내용은 그대로 남는다 |
| 일자별 채팅 이력 (Daily Chat Log) | 메시지를 작성 일시 기준(한국 표준시)으로 날짜별로 묶어 조회한 것. 별도로 저장하는 엔티티가 아니다 |
| 일정 변경 요청 (Change Request) | 팀원이 본인 관련 일정을 바꿔 달라고 채팅으로 보내는 메시지. 대상 일정을 참조하며, 별도의 처리 상태는 두지 않는다 |

## 5. 엔티티와 관계

```
User ──< TeamMembership >── Team
                (role: 팀장 | 팀원)

Team 1 ──< N Schedule
Schedule N >──< N TeamMembership  (관련 팀원, role = 팀원만)
Team 1 ── 1 ChatRoom
ChatRoom 1 ──< N Message
User 1 ──< N Message              (작성자)
Message (유형: 일반 | 일정 변경 요청) ── 0..1 Schedule   (요청 대상 일정)
```

| 엔티티 | 주요 속성 |
|--------|-----------|
| User | 사용자 ID, 이메일(유일), 비밀번호, 이름 |
| Team | 팀 ID, 팀 이름, 초대 코드, 생성자 ID(기록용) |
| TeamMembership | 사용자 ID, 팀 ID, 역할(팀장/팀원). 팀장 여부는 이 역할을 기준으로 판단한다 |
| Schedule | 일정 ID, 팀 ID, 제목, 시작 일시, 종료 일시, 작성자, 최종 수정자, 수정 일시, 삭제 여부 |
| ChatRoom | 채팅방 ID, 팀 ID |
| Message | 메시지 ID, 채팅방 ID, 작성자 ID, 내용, 작성 일시, 메시지 유형, 대상 일정 ID(유형이 변경 요청이면 필수, 일반이면 없음) |

## 6. 핵심 비즈니스 규칙

| ID | 규칙 |
|----|------|
| BR-01 | 로그인한 사용자만 모든 기능을 이용할 수 있다 |
| BR-02 | 팀 일정은 해당 팀의 모든 구성원에게 공유된다 |
| BR-03 | 팀 일정을 추가·수정·삭제할 수 있는 사람은 팀장뿐이다 |
| BR-04 | 팀원은 팀 일정을 조회만 할 수 있으며 직접 수정할 수 없다 |
| BR-05 | 팀원은 본인이 관련 팀원으로 등록된 일정에 대해서만 채팅으로 변경을 요청할 수 있다 |
| BR-06 | 일정 변경 요청은 처리 상태를 관리하지 않는다. 팀장이 채팅 내용을 확인한 뒤 직접 일정을 수정한다 |
| BR-07 | 채팅 메시지는 작성 일시 기준(한국 표준시)으로 일자별로 조회한다 |
| BR-08 | 캘린더와 채팅은 한 화면에서 동시에 보여 준다. 작은 화면에서는 캘린더와 채팅을 탭으로 전환해 보여 주는 것으로 대신한다 |
| BR-09 | 사용자는 자신이 속한 팀의 일정과 채팅에만 접근할 수 있다 |
| BR-10 | 한 사용자는 여러 팀에 속할 수 있다 |
| BR-11 | 팀장은 팀을 만든 사용자 1명이다 |
| BR-12 | 팀을 만들면 초대 코드가 생성되고, 팀원은 초대 코드로만 팀에 참여한다 |
| BR-13 | 관련 팀원은 같은 팀의 팀원 역할 구성원만 될 수 있으며, 팀장은 관련 팀원이 될 수 없다 |
| BR-14 | 일정의 종료 일시는 시작 일시와 같거나 그 이후여야 한다 |
| BR-15 | 일정을 삭제하면 캘린더에서는 사라지지만, 그 일정을 참조하는 변경 요청 메시지는 그대로 남고 대상 일정이 "삭제됨"으로 표시된다 |
| BR-16 | 계정은 이메일과 비밀번호로 회원가입해 만든다. 이미 가입한 이메일로는 가입할 수 없다 |
| BR-17 | 팀을 만들면 그 팀의 채팅방이 함께 만들어진다 |
| BR-18 | 초대 코드는 팀마다 유일하며, 팀장만 확인할 수 있다 |
| BR-19 | 여러 팀에 속한 사용자는 팀을 전환할 수 있으며, 전환하면 선택한 팀의 일정과 채팅만 보인다 |
| BR-20 | 채팅 이력은 무기한 보관한다. 사용자가 탈퇴해도 메시지는 남기고 작성자 표시만 "탈퇴한 사용자"로 익명화한다 |

## 7. 주요 유스케이스

ID는 고정하고, 행은 사용 흐름 순서로 배치한다.

| ID | 유스케이스 | 액터 | 주요 흐름 | 수용 기준 | 관련 BR |
|----|-----------|------|-----------|-----------|---------|
| UC-12 | 회원가입 | 사용자 | 이메일, 비밀번호, 이름을 입력해 계정을 만든다 | 가입 후 로그인할 수 있다. 이미 가입한 이메일은 거부된다 | BR-16 |
| UC-01 | 로그인 | 사용자 | 계정 정보를 입력하고 인증되면 소속 팀을 선택해 팀 화면으로 들어간다. 소속 팀이 없으면 팀 생성 또는 초대 코드 입력 화면으로 간다. 들어간 뒤에도 다른 소속 팀으로 전환할 수 있다 | 로그인하지 않은 상태로 기능에 접근하면 거부된다. 팀을 전환하면 선택한 팀의 일정과 채팅만 표시된다 | BR-01, BR-10, BR-19 |
| UC-09 | 팀 생성 | 사용자 | 팀 이름을 입력해 팀을 만든다 | 만든 사용자가 팀장이 되고, 초대 코드와 팀 채팅방이 생성된다. 초대 코드는 팀장에게만 표시된다 | BR-11, BR-12, BR-17, BR-18 |
| UC-10 | 초대 코드로 팀 참여 | 사용자 | 초대 코드를 입력해 팀에 참여한다 | 유효한 코드면 팀원으로 등록된다. 잘못된 코드는 거부된다. 이미 소속된 팀이면 중복 등록되지 않는다 | BR-10, BR-12 |
| UC-02 | 팀 일정 조회 | 팀장, 팀원 | 월·주·일 단위를 고르면 해당 기간의 팀 일정이 표시된다 | 선택한 기간과 겹치는, 현재 팀의 삭제되지 않은 일정만 표시된다. 다른 팀의 일정은 표시되지 않는다 | BR-02, BR-09 |
| UC-03 | 팀 일정 추가 | 팀장 | 캘린더에서 일정 정보와 관련 팀원을 입력하고 저장한다 | 저장한 일정이 팀 구성원이 조회할 때 캘린더에 보인다. 종료 일시가 시작 일시보다 앞서거나 관련 팀원에 팀장을 지정하면 거부된다. 팀원은 추가를 시도하면 거부된다 | BR-03, BR-13, BR-14 |
| UC-04 | 팀 일정 수정 | 팀장 | 채팅을 보면서 캘린더에서 기존 일정을 수정한다 | 수정 내용이 팀 구성원이 조회할 때 보인다. 팀원은 수정을 시도하면 거부된다 | BR-03, BR-04, BR-08 |
| UC-11 | 팀 일정 삭제 | 팀장 | 캘린더에서 기존 일정을 삭제한다 | 삭제된 일정은 팀 구성원이 조회할 때 캘린더에 보이지 않는다. 그 일정을 참조한 변경 요청 메시지는 남고 대상 일정이 "삭제됨"으로 표시된다. 팀원은 삭제를 시도하면 거부된다 | BR-03, BR-15 |
| UC-05 | 채팅 대화 | 팀장, 팀원 | 캘린더 옆의 채팅방에서 메시지를 주고받는다 | 보낸 메시지가 작성자, 작성 일시와 함께 채팅방에 표시된다. 다른 팀의 채팅방에는 접근할 수 없다 | BR-08, BR-09 |
| UC-06 | 일정 변경 요청 | 팀원 | 본인 관련 일정을 골라 채팅으로 변경 요청을 보낸다 | 대상 일정이 함께 표시된 요청 메시지가 채팅방에 남는다. 관련 팀원이 아닌 일정은 요청할 수 없다 | BR-05 |
| UC-07 | 변경 요청 반영 | 팀장 | 채팅에서 요청을 확인한 뒤 UC-04로 일정을 수정한다 | 수정된 일정이 캘린더에 반영되고, 요청 메시지는 변하지 않고 그대로 남는다 | BR-06 |
| UC-08 | 일자별 채팅 이력 조회 | 팀장, 팀원 | 날짜를 골라 그날의 채팅 이력을 조회한다 | 선택한 날짜(한국 표준시)에 작성된 메시지만 표시된다 | BR-07 |
