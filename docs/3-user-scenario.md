# Team CalTalk 사용자 시나리오

버전 0.2 · 최종 수정일 2026-09-30

참조 문서: `docs/1-domain-definition.md` (도메인 정의서 v0.4), `docs/2-PRD.md` (PRD v0.8)

## 1. 개요

### 1.1 목적

도메인 정의서의 유스케이스(UC)와 PRD의 기능 요구사항(FR)을 사용자가 실제로 쓰는 순서대로 풀어 쓴다. 각 시나리오는 화면·API 확인과 테스트의 기준으로 쓴다.

### 1.2 작성 원칙

- 가상 인물의 배경이나 성격을 묘사하는 페르소나 시나리오는 쓰지 않는다(PRD 5.2). 역할 기준의 사용 흐름만 다룬다.
- 두 참조 문서에 없는 기능은 쓰지 않는다. 정해지지 않은 부분은 "미결(Q-xx)"로 표시한다.
- 권한 검사와 거부는 모두 서버에서 처리한다(NFR-03). 화면에서 버튼을 숨기는 것은 보조 수단일 뿐이다.
- 날짜 경계와 화면 표시는 한국 표준시 기준이다(NFR-05).

### 1.3 액터

| 액터 | 설명 |
|------|------|
| 가입 전 사용자 | 아직 계정이 없는 사람. 회원가입만 할 수 있다 |
| 사용자 | 로그인했지만 역할은 팀마다 다르다. 팀 생성·참여의 액터 |
| 팀장 | 팀을 만든 사용자. 팀마다 1명. 일정 추가·수정·삭제, 초대 코드 확인 가능 |
| 팀원 | 초대 코드로 참여한 구성원. 일정 조회, 채팅, 본인 관련 일정의 변경 요청 가능 |

한 사용자는 팀 A에서는 팀장, 팀 B에서는 팀원일 수 있다(BR-10). 역할은 현재 선택한 팀 기준으로 판단한다.

## 3. 시나리오 상세

### SC-01 회원가입

- 관련: UC-12 / BR-16 / FR-01
- 액터: 가입 전 사용자
- 사전 조건: 로그인하지 않은 상태

**흐름**
1. 회원가입 화면에서 이메일, 비밀번호, 이름을 입력한다.
2. 가입을 요청한다.
3. 서버가 계정을 만든다. 비밀번호는 원문으로 저장하지 않는다(NFR-04).

**기대 결과**
- 가입한 이메일과 비밀번호로 로그인할 수 있다(SC-02).

**예외·거부**
- E1. 이미 가입한 이메일이면 가입이 거부되고 계정이 만들어지지 않는다.
- E2. 비밀번호가 8자 미만이면 가입이 거부된다(NFR-04).

### SC-02 로그인과 팀 선택

- 관련: UC-01 / BR-01, BR-10 / FR-02, FR-03
- 액터: 사용자
- 사전 조건: 계정이 있다(SC-01)

**흐름**
1. 로그인 화면에서 이메일과 비밀번호를 입력한다.
2. 인증되면 서버가 JWT 토큰을 발급하고(NFR-08), 소속 팀 목록에서 팀을 골라 팀 메인 화면으로 들어간다.
3. 소속 팀이 없으면 팀 시작 화면(팀 생성 또는 초대 코드 입력)으로 간다.

**기대 결과**
- 팀 메인 화면에 선택한 팀의 캘린더와 채팅이 보인다.

**예외·거부**
- E1. 이메일 또는 비밀번호가 맞지 않으면 인증되지 않고 들어갈 수 없다.
- E2. 로그인하지 않은 상태로 회원가입·로그인 외 기능(일정 조회, 채팅 등)을 요청하면 서버가 거부한다(BR-01).
- E3. 토큰이 없거나 유효하지 않은 상태로 기능을 요청해도 서버가 거부한다(BR-01, NFR-08).

### SC-03 팀 생성과 초대 코드 확인

- 관련: UC-09 / BR-11, BR-12, BR-17, BR-18 / FR-04, FR-05
- 액터: 사용자(생성 후 팀장)
- 사전 조건: 로그인 상태

**흐름**
1. 팀 시작 화면에서 팀 이름을 입력하고 팀을 만든다.
2. 서버가 팀, 팀마다 유일한 초대 코드, 팀 채팅방을 함께 만들고, 만든 사용자를 팀장으로 등록한다.
3. 팀 메인 화면 상단에서 초대 코드를 확인한다.
4. 초대 코드를 팀원이 될 사람에게 서비스 밖에서 전달한다(전달 기능은 제공하지 않는다).

**기대 결과**
- 만든 사용자가 그 팀의 유일한 팀장이 된다.
- 초대 코드는 팀장 화면에만 표시된다.

**예외·거부**
- E1. 팀원이 초대 코드를 요청하면 서버가 거부하고, 팀원 화면에는 초대 코드가 표시되지 않는다(BR-18).

### SC-04 초대 코드로 팀 참여

- 관련: UC-10 / BR-10, BR-12 / FR-06
- 액터: 사용자(참여 후 팀원)
- 사전 조건: 로그인 상태, 팀장에게서 초대 코드를 받았다

**흐름**
1. 팀 시작 화면에서 초대 코드를 입력한다.
2. 서버가 코드에 맞는 팀을 찾아 사용자를 팀원으로 등록한다.
3. 참여한 팀의 팀 메인 화면으로 들어간다.

**기대 결과**
- 사용자가 팀원 역할로 팀에 소속되고, 팀 일정과 채팅을 볼 수 있다.

**예외·거부**
- E1. 존재하지 않는 코드를 입력하면 거부되고 어느 팀에도 등록되지 않는다.
- E2. 이미 소속된 팀의 코드를 입력하면 중복 등록되지 않는다.

### SC-05 팀 일정 조회 (월·주·일)

- 관련: UC-02 / BR-02, BR-09 / FR-07
- 액터: 팀장, 팀원
- 사전 조건: 로그인 상태, 팀을 선택했다

**흐름**
1. 캘린더에서 월·주·일 단위 중 하나를 고른다.
2. 서버가 선택한 기간(한국 표준시 기준)과 겹치는 현재 팀의 일정을 돌려준다.

**기대 결과**
- 현재 팀의 삭제되지 않은 일정만 보인다. 여러 날에 걸친 일정은 겹치는 모든 날에 보인다.
- 팀장과 팀원이 같은 일정을 본다(BR-02).

**예외·거부**
- E1. 소속되지 않은 팀의 일정을 요청하면 서버가 거부한다(BR-09).
- E2. 삭제된 일정은 표시되지 않는다(BR-15).

### SC-06 팀 일정 추가

- 관련: UC-03 / BR-03, BR-13, BR-14 / FR-08
- 액터: 팀장
- 사전 조건: 로그인 상태, 현재 팀의 팀장이다

**흐름**
1. 캘린더에서 일정 입력 화면을 연다.
2. 제목, 시작 일시, 종료 일시를 입력한다.
3. 같은 팀의 팀원 중에서 관련 팀원을 고른다.
4. 저장한다.

**기대 결과**
- 팀 구성원 모두가 조회할 때 새 일정이 캘린더에 보인다(SC-05).
- 작성자가 기록된다.

**예외·거부**
- E1. 종료 일시가 시작 일시보다 앞서면 거부된다(BR-14). 같은 것은 허용된다.
- E2. 관련 팀원에 팀장을 지정하면 거부된다(BR-13).
- E3. 관련 팀원에 다른 팀 사용자를 지정하면 거부된다(BR-13).
- E4. 팀원이 일정 추가를 요청하면 서버가 거부한다(BR-03). 팀원 화면에는 일정 입력 버튼이 없다.

### SC-07 팀 일정 수정

- 관련: UC-04 / BR-03, BR-04, BR-08 / FR-09
- 액터: 팀장
- 사전 조건: 현재 팀의 팀장이다, 수정할 일정이 있다

**흐름**
1. 캘린더에서 일정을 골라 수정 화면을 연다. 채팅은 같은 화면에 그대로 보인다.
2. 제목, 일시, 관련 팀원을 고친다.
3. 저장한다.

**기대 결과**
- 수정 내용이 팀 구성원이 조회할 때 보인다.
- 작성자는 그대로이고, 최종 수정자와 수정 일시가 기록된다.

**예외·거부**
- E1. SC-06의 입력 검사(E1~E3)를 똑같이 적용한다.
- E2. 팀원이 수정을 요청하면 서버가 거부한다(BR-04).

### SC-08 팀 일정 삭제

- 관련: UC-11 / BR-03, BR-15 / FR-10
- 액터: 팀장
- 사전 조건: 현재 팀의 팀장이다, 삭제할 일정이 있다

**흐름**
1. 일정 수정 화면에서 삭제를 누른다.
2. 서버가 데이터를 지우지 않고 삭제 여부만 표시한다(논리 삭제).

**기대 결과**
- 팀 구성원 모두의 캘린더에서 그 일정이 사라진다.
- 그 일정을 참조한 변경 요청 메시지는 남는다(SC-12).

**예외·거부**
- E1. 팀원이 삭제를 요청하면 서버가 거부한다(BR-03).

### SC-09 채팅 대화

- 관련: UC-05 / BR-08, BR-09 / FR-11
- 액터: 팀장, 팀원
- 사전 조건: 로그인 상태, 팀을 선택했다

**흐름**
1. 캘린더 옆 채팅방 입력창에 메시지를 쓰고 보낸다.
2. 서버가 메시지를 작성자, 작성 일시와 함께 저장한다.
3. 같은 팀의 다른 구성원 화면에 Long Polling으로 새 메시지가 도착한다.

**기대 결과**
- 메시지가 작성자, 작성 일시(한국 표준시)와 함께 채팅방에 표시된다.

**예외·거부**
- E1. 소속되지 않은 팀의 채팅방에 메시지를 보내거나 조회하면 서버가 거부한다(BR-09).
- 1,000명 동시 접속 상태에서도 메시지는 보낸 뒤 p95 2초 이내에 다른 구성원 화면에 표시된다(NFR-01).

### SC-10 일정 변경 요청

- 관련: UC-06 / BR-05, BR-06 / FR-12
- 액터: 팀원
- 사전 조건: 현재 팀의 팀원이다, 본인이 관련 팀원으로 등록된 일정이 있다

**흐름**
1. 채팅 영역에서 변경 요청을 고른다.
2. 본인이 관련 팀원인 일정 중 하나를 고른다.
3. 바꾸고 싶은 내용을 메시지로 쓰고 보낸다.
4. 서버가 관련 팀원 여부를 확인하고, 대상 일정을 참조한 변경 요청 메시지로 저장한다.

**기대 결과**
- 채팅방에 대상 일정이 함께 표시된 요청 메시지가 남고, 팀장을 포함한 팀 구성원이 본다.
- 요청 메시지에는 처리 상태(대기·완료 등)가 없다(BR-06).

**예외·거부**
- E1. 본인이 관련 팀원이 아닌 일정으로 요청하면 서버가 거부한다(BR-05). 화면의 일정 선택 목록에도 나오지 않는다.
- E2. 다른 팀의 일정으로 요청하면 서버가 거부한다(BR-09).
- E3. 팀장은 관련 팀원이 될 수 없으므로 변경 요청을 보낼 수 없다(BR-13). 팀장은 SC-07로 직접 수정한다.

### SC-11 변경 요청을 보고 일정 반영 (차별점)

- 관련: UC-07, UC-04 / BR-06, BR-08 / FR-09, FR-12, FR-14
- 액터: 팀장
- 사전 조건: SC-10으로 변경 요청 메시지가 채팅방에 있다

**흐름**
1. 채팅방에서 변경 요청 메시지와 대상 일정을 확인한다.
2. 필요하면 같은 채팅방에서 팀원과 대화해 내용을 정한다(SC-09).
3. 채팅을 보면서 캘린더에서 대상 일정을 수정한다(SC-07).

**기대 결과**
- 수정된 일정이 팀 구성원의 캘린더에 반영된다.
- 요청 메시지는 바뀌지 않고 그대로 남아, 일정을 바꾼 근거가 채팅 이력으로 남는다.
- 요청을 반영하지 않는 경우에도 별도 처리(거절·완료 표시)는 없다(BR-06).

**예외·거부**
- E1. 팀원은 요청 메시지를 보고도 일정을 직접 수정할 수 없다(SC-07 E2).

### SC-12 삭제된 일정을 참조한 요청 메시지

- 관련: UC-11, UC-06 / BR-15 / FR-10, FR-12
- 액터: 팀장, 팀원
- 사전 조건: 변경 요청 메시지가 참조하는 일정을 팀장이 삭제했다(SC-08)

**흐름**
1. 구성원이 채팅방 또는 일자별 이력(SC-13)에서 그 요청 메시지를 본다.

**기대 결과**
- 요청 메시지는 지워지지 않고 남는다.
- 메시지의 대상 일정이 "삭제됨"으로 표시된다.
- 캘린더에는 그 일정이 보이지 않는다.

### SC-13 일자별 채팅 이력 조회

- 관련: UC-08 / BR-07, BR-20 / FR-13, FR-15
- 액터: 팀장, 팀원
- 사전 조건: 로그인 상태, 팀을 선택했다

**흐름**
1. 채팅 영역의 날짜 선택에서 날짜를 고른다.
2. 서버가 그 날짜(한국 표준시 00:00~24:00)에 작성된 현재 팀의 메시지를 돌려준다.

**기대 결과**
- 선택한 날짜에 작성된 메시지만 표시된다. 한국 표준시 23:59에 쓴 메시지는 그날에, 다음 날 00:00에 쓴 메시지는 다음 날에 보인다.
- 오래된 날짜의 메시지도 조회된다(무기한 보관).
- 변경 요청 메시지도 대상 일정과 함께 보인다(삭제된 일정은 SC-12).

**예외·거부**
- E1. 소속되지 않은 팀의 이력을 요청하면 서버가 거부한다(BR-09).
- 회원 탈퇴 기능은 이번 개발에서 제외되므로(PRD 5.2) 탈퇴한 사용자의 메시지는 생기지 않는다.

### SC-14 팀 전환

- 관련: UC-01 / BR-09, BR-10, BR-19 / FR-03
- 액터: 사용자(두 개 이상의 팀에 소속)
- 사전 조건: 로그인 상태, 팀 메인 화면에 들어와 있다

**흐름**
1. 팀 메인 상단의 팀 선택에서 다른 소속 팀을 고른다.
2. 화면이 선택한 팀의 캘린더와 채팅으로 바뀐다.

**기대 결과**
- 선택한 팀의 일정과 채팅만 보인다. 이전 팀의 일정·메시지는 섞이지 않는다.
- 역할도 선택한 팀 기준으로 바뀐다. 예: 팀 A의 팀장이 팀원으로 속한 팀 B로 바꾸면 일정 입력 버튼과 초대 코드가 보이지 않고, 서버도 팀 B에서의 일정 추가를 거부한다.

**예외·거부**
- E1. 팀 선택 목록에는 소속 팀만 나온다. 소속되지 않은 팀을 요청하면 서버가 거부한다(BR-09).

### SC-15 작은 화면에서 캘린더·채팅 탭 전환

- 관련: UC-04, UC-05 / BR-08 / FR-14, NFR-02
- 액터: 팀장, 팀원
- 사전 조건: 모바일 등 작은 화면의 웹 브라우저로 팀 메인 화면에 들어와 있다

**흐름**
1. 캘린더 탭에서 일정을 본다.
2. 채팅 탭으로 바꿔 메시지를 읽고 보낸다.
3. 다시 캘린더 탭으로 돌아온다.

**기대 결과**
- 넓은 화면에서는 캘린더와 채팅이 동시에 보이고, 작은 화면에서는 탭으로 전환해 본다.
- 기능과 권한은 넓은 화면과 같다. 팀장은 채팅 탭에서 요청을 보고 캘린더 탭에서 일정을 수정한다(SC-11).
- 네이티브 앱은 없고 반응형 웹으로만 지원한다.

### SC-16 로그아웃

- 관련: BR-01 / FR-16 (도메인 정의서에 대응 UC 없음)
- 액터: 사용자
- 사전 조건: 로그인한 상태(SC-02)

**흐름**
1. 팀 메인 상단의 로그아웃 버튼을 누른다.
2. 로그인 화면으로 돌아간다.

**기대 결과**
- 다시 로그인하기 전까지 회원가입·로그인 외 기능(일정 조회, 채팅 등)을 쓸 수 없다.
