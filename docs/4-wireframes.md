# Team CalTalk 와이어프레임

버전 0.5 · 최종 수정일 2026-09-30

참조 문서: `docs/1-domain-definition.md` (도메인 정의서 v0.4), `docs/2-PRD.md` (PRD v0.8), `docs/3-user-scenario.md` (사용자 시나리오 v0.2)

## 1. 개요

### 1.1 목적

PRD 9장 화면 구성을 배치와 구성 요소 수준으로 그린다. 개발자가 화면을 만들 때 "어디에 무엇이 있는지"의 기준으로 쓴다.

### 1.2 작성 원칙

- 배치와 구성 요소만 다룬다. 색상, 폰트 같은 시각 디자인은 다루지 않는다.
- 접근성은 고려하지 않는다(NFR-07).
- 캘린더와 채팅은 한 화면에 함께 나타낸다. 화면이 좁아 둘을 함께 나타낼 수 없으면 탭 전환 대신 채팅을 [채팅 보기] / [채팅 숨기기](Show/Hide)로 처리한다. 다른 문서의 "탭 전환" 표현보다 이 결정을 따르며, 불일치는 10장에 정리했다.
- 그림은 ┌ ─ ┐ │ └ ┘ 같은 박스 문자로 그린다.
- 문서에 없는 기능과 버튼은 그리지 않는다. 단, WF-04(메인 대시보드)의 알림, 온라인 사용자, 최근 활동 표시줄, [오늘로 이동]은 사용자 요청으로 추가했으며 11장에 불일치로 정리했다. 그 밖에는 PRD 5.2 제외 항목(알림, 파일 첨부, 외부 연동, 회원 탈퇴, 변경 요청 처리 상태, 충돌 자동 감지, 반복 일정)은 나오지 않는다.
- 화면의 안내 문구는 모두 예시다. 실제 문구는 구현할 때 정한다.
- 문서에 정해지지 않은 부분은 그림에 `[미결-n]`으로 자리만 표시하고, 9장에 선택지와 함께 정리했다.
- 버튼을 숨기는 것은 보조 수단이다. 권한 검사와 거부는 서버가 한다(NFR-03).
- 일시는 모두 한국 표준시로 표시한다(NFR-05).

### 1.3 그림 표기

| 표기 | 뜻 |
|------|----|
| `[ 텍스트 ]` | 버튼 |
| `[____________]` | 입력창 |
| `[ 항목 v ]` | 선택 목록 |
| `[x] / [ ]` | 체크됨 / 체크 안 됨 |
| `( 월 \| (주) \| 일 )` | 전환 버튼. 괄호로 감싼 것이 현재 선택 |
| `[미결-n]` | 문서에 정해지지 않은 자리. 9장 참고 |

## 3. 화면 이동 흐름

```
 [로그인 전]                         [로그인 후]

 WF-01 회원가입 --가입 성공--> WF-02 로그인 <------------------+
      ^                            |                          |
      +--- "로그인" 링크 ----------+                          |
                                   | 인증 성공                |
                +------------------+------------------+       |
                | 소속 팀 없음                        | 소속 팀 있음
                v                                     v       |
         WF-03 팀 시작 ---만들기(팀장)/참여(팀원)--> WF-04 / 05 / 06
                                                      팀 메인 |
                                                      (폭에 따라 하나)
                                                        |     |
                          +--------------+--------------+     |
                          |              |              |     |
                    팀 전환(상단)   일정 추가/수정   로그아웃 -+
                    (같은 화면,     (팀장만)
                     팀만 바뀜)          v
                                   WF-09 일정 입력·수정·삭제
                                   (저장/삭제/닫기 후 팀 메인)

 팀 메인 안에서
   WF-08 채팅 --(팀원) [변경 요청]--------------> WF-10 변경 요청 보내기
   WF-08 채팅 --(팀장) 요청 메시지를 보며-------> WF-11 (WF-09를 사용)
   WF-08 채팅 --대상 일정이 삭제된 요청 메시지--> WF-12 "삭제됨" 표시
   WF-04(넓은 화면) <--화면 폭 변화--> WF-05 <-[채팅 보기]/[채팅 숨기기]-> WF-06

 로그인하지 않은 상태로 WF-01, WF-02 외 화면을 열면 WF-02로 보낸다 (BR-01).
```

- 이미 팀이 있는 사용자가 팀을 더 만들거나 다른 팀에 참여하는 진입 위치는 정해지지 않았다 → [미결-1]

## 4. 인증 화면

### WF-01 회원가입

- 관련: FR-01 / SC-01
- 진입: WF-02의 "회원가입" 링크
- 이동: 가입 성공 → WF-02

```
┌────────────────────────────────────────────┐
│                                            │
│                Team CalTalk                │
│                  회원가입                  │
│                                            │
│  이메일     [__________________________]   │
│  비밀번호   [__________________________]   │
│             (8자 이상)                     │
│  이름       [__________________________]   │
│                                            │
│           [      가입하기      ]           │
│                                            │
│         이미 계정이 있나요? 로그인         │
│                                            │
└────────────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| 입력창 3개 | 이메일, 비밀번호, 이름 |
| 가입하기 버튼 | 가입을 요청한다 |
| 로그인 링크 | WF-02로 이동 |

- 팀장/팀원 차이: 없음. 가입 전이라 역할이 없다.
- 주요 상태

| 상황 | 표시 예시 | 근거 |
|------|-----------|------|
| 이미 가입한 이메일 (거부) | "이미 가입한 이메일입니다" | SC-01 E1 |
| 비밀번호 8자 미만 (거부) | "비밀번호는 8자 이상이어야 합니다" | SC-01 E2 |

### WF-02 로그인

- 관련: FR-02, FR-03 / SC-02
- 진입: 처음 접속, 회원가입 성공, 로그아웃, 토큰이 없거나 유효하지 않을 때
- 이동: 인증 성공 → 소속 팀이 있으면 팀 메인(WF-04/05/06), 없으면 WF-03

```
┌────────────────────────────────────────────┐
│                                            │
│                Team CalTalk                │
│                   로그인                   │
│                                            │
│  이메일     [__________________________]   │
│  비밀번호   [__________________________]   │
│                                            │
│           [       로그인       ]           │
│                                            │
│          계정이 없나요? 회원가입           │
│                                            │
└────────────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| 입력창 2개 | 이메일, 비밀번호 |
| 로그인 버튼 | 인증을 요청한다 |
| 회원가입 링크 | WF-01로 이동 |

- 팀장/팀원 차이: 없음. 역할은 팀마다 다르며 팀에 들어간 뒤에 정해진다.
- 주요 상태

| 상황 | 표시 예시 | 근거 |
|------|-----------|------|
| 이메일 또는 비밀번호 불일치 (거부) | "이메일 또는 비밀번호가 맞지 않습니다" | SC-02 E1 |
| 로그인 없이·토큰 오류로 다른 기능 접근 (서버 거부) | 이 화면으로 돌아온다 | SC-02 E2, E3 |

## 5. 팀 시작

### WF-03 팀 시작 (소속 팀 없음)

- 관련: FR-03, FR-04, FR-06 / SC-02, SC-03, SC-04
- 진입: 로그인했는데 소속 팀이 없을 때
- 이동: 팀 만들기 성공(팀장) 또는 참여 성공(팀원) → 팀 메인

```
┌────────────────────────────────────────────────────────┐
│  Team CalTalk                          [ 로그아웃 ]    │
├────────────────────────────────────────────────────────┤
│                                                        │
│   아직 소속된 팀이 없습니다.                           │
│                                                        │
│   ┌────────────────────────┐  ┌──────────────────────┐ │
│   │  팀 만들기             │  │  팀 참여하기         │ │
│   │                        │  │                      │ │
│   │  팀 이름               │  │  초대 코드           │ │
│   │  [________________]    │  │  [_______________]   │ │
│   │                        │  │                      │ │
│   │  [   팀 만들기   ]     │  │  [   참여하기   ]    │ │
│   └────────────────────────┘  └──────────────────────┘ │
│                                                        │
└────────────────────────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| 팀 만들기 영역 | 팀 이름 입력 + 버튼. 만들면 초대 코드와 채팅방이 함께 생기고 만든 사람이 팀장이 된다 |
| 팀 참여하기 영역 | 초대 코드 입력 + 버튼. 성공하면 팀원으로 등록된다 |
| 로그아웃 버튼 | 누르면 WF-02로 돌아간다 (직접 정한 배치, 10장 A-1) |

- 팀장/팀원 차이: 아직 역할이 없다. 만들면 팀장, 참여하면 팀원이 된다.
- 소속 팀이 없을 때만 나오는 화면이다. 이미 팀이 있는 사용자의 팀 추가·참여 위치는 → [미결-1]
- 좁은 화면에서는 두 영역을 위아래로 쌓는다(직접 정한 배치, 10장 A-2).
- 주요 상태

| 상황 | 표시 예시 | 근거 |
|------|-----------|------|
| 존재하지 않는 초대 코드 (거부) | "초대 코드가 올바르지 않습니다" | SC-04 E1 |
| 이미 소속된 팀의 코드 | "이미 참여한 팀입니다" (중복 등록 안 됨) | SC-04 E2 |

## 6. 팀 메인

팀 메인은 화면 폭에 따라 WF-04(넓은 화면), WF-05·WF-06(작은 화면) 중 하나로 나타난다. 기능과 권한은 셋이 같다. 단, 알림·온라인 사용자·최근 활동 표시줄·[오늘로 이동]은 WF-04에만 그렸다. 폭의 기준값은 문서에 없어 구현할 때 정한다.

### WF-04 3.3 메인 대시보드 (데스크톱)

```
│                                                                                          │
│ ┌──────────────────────────────────────────────────────────────────────────────────────┐ │
│ │ 최근 활동                                                                            │ │
│ ├──────────────────────────────────────────────────────────────────────────────────────┤ │
│ │ 10:25 홍길동 - "발표" 일정 수정                                                      │ │
```

```
│ └──────────────────────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

| 구성 요소 | 위치 | 설명 |
|-----------|------|------|
| 팀 선택·전환 | 상단 바 왼쪽 | 소속 팀만 나온다. 고르면 선택한 팀의 일정과 채팅만 보인다(BR-19) |
| 팀 추가·참여 진입 | 팀 선택 옆 | [미결-1] 자리만 표시 |
| 초대 코드 | 상단 바 | 팀장에게만 표시(BR-18) |
| 알림 | 상단 메뉴 | 사용자 요청으로 추가. PRD 5.2에서 이번 개발 제외로 정한 기능이라 11장에 불일치로 정리 |
| 사용자 이름, 로그아웃 | 상단 메뉴 오른쪽 | 로그아웃하면 WF-02로 이동(FR-16) |
| 캘린더 이동 | 캘린더 상단 | 이전/다음 기간으로 이동 |
| 월·주·일 전환 | 캘린더 상단 | 3가지 뷰 중 하나 선택. WF-07 참고 |
| [+ 새 일정] 버튼 | 캘린더 영역 맨 아래 | 팀장에게만 표시. 누르면 WF-09(추가) |
| [오늘로 이동] 버튼 | 캘린더 영역 맨 아래 | 오늘 날짜가 있는 기간으로 이동. 사용자 요청으로 추가(문서에 없는 새 요소) |
| 일정 표시 | 캘린더 본문 | 선택한 기간과 겹치는, 삭제되지 않은 현재 팀 일정만. 여러 날 일정은 겹치는 모든 날에 표시 |
| 채팅 영역 | 오른쪽 | 메시지 목록, 입력창, [전송]. 상세는 WF-08 |
| 온라인 사용자 | 채팅 영역 맨 아래 | 지금 접속한 팀 구성원 수와 이름. 사용자 요청으로 추가(문서에 없는 새 요소) |
| 최근 활동 표시줄 | 화면 맨 아래 별도 박스 | 최근 일정 수정, 변경 요청 등 팀 활동을 한 줄로 표시. 사용자 요청으로 추가(문서에 없는 새 요소) |

- 팀장/팀원 차이

| 요소 | 팀장 | 팀원 |
|------|:----:|:----:|
| 초대 코드 | 표시 | 없음 |
| [+ 새 일정] 버튼 | 표시 | 없음 |
| 일정을 눌렀을 때 | 수정 창(WF-09) | 조회만 |
| 채팅의 [변경 요청] 버튼 | 없음 | 표시 |

- 팀을 전환하면 역할도 그 팀 기준으로 바뀌어 위 표시가 달라진다(SC-14).
- 주요 상태

| 상태 | 표시 예시 | 근거 |
|------|-----------|------|
| 캘린더 빈 상태 (해당 기간에 일정 없음) | 캘린더 본문에 "이 기간에 일정이 없습니다" | SC-05 |
| 채팅 빈 상태 (메시지 없음) | 채팅 본문에 "아직 메시지가 없습니다" | SC-09 |
| 소속되지 않은 팀 요청 (서버 거부) | "접근 권한이 없습니다" 후 팀 선택으로 복귀 | SC-05 E1, SC-14 E1 |
| 팀원이 일정 추가·수정·삭제 시도 (서버 거부) | "팀장만 할 수 있습니다" | SC-06 E4, SC-07 E2, SC-08 E1 |

### WF-06 팀 메인 - 작은 화면, 채팅 보임

- 관련: FR-14, NFR-02 / SC-15
- 배치: 상단 바는 그대로 두고, 본문 자리를 채팅이 차지한다. 화면 맨 아래의 버튼이 [채팅 숨기기]로 바뀐다(Hide). 누르면 WF-05로 돌아가며 캘린더는 보던 그대로 다시 보인다.

팀원 화면

```
┌──────────────────────────────┐
│ Team CalTalk     [로그아웃]  │
│ [ 팀 A v ] [미결-1]          │

│ 채팅                         │
│ 날짜 [ 미결-2 v ]            │

│ 내일 회의 몇 시예요?         │
│ 홍길동 10:15                 │
│ 오후 2시입니다.              │
│ ──────────────────────────── │
│ [________________] [ 전송 ]  │
│ [ 변경 요청 ]                │
├──────────────────────────────┤
│       [ 채팅 숨기기 ]        │

```

| 구성 요소 | 설명 |
|-----------|------|
| 상단 바 | 팀 선택, 로그아웃은 항상 보인다. 초대 코드는 팀장에게만 표시 |
| 캘린더 | WF-05에서 보인다. 구성은 WF-04 왼쪽과 같다 |
| 채팅 | WF-06에서 보인다. 구성은 WF-04 오른쪽(WF-08)과 같다 |
| [채팅 보기] / [채팅 숨기기] | 화면 맨 아래에 하나만 있다. 채팅 숨김 상태에서는 [채팅 보기], 보임 상태에서는 [채팅 숨기기] |

- 팀장/팀원 차이: WF-04와 같다(초대 코드, [+ 새 일정] 버튼, [변경 요청]).
- 채팅을 숨겨도 새 메시지 수신(Long Polling)은 멈추지 않는다. 다시 보이면 그동안 온 메시지가 목록에 있다.
- 팀장이 요청을 반영할 때는 [채팅 보기]로 요청을 읽고, [채팅 숨기기]로 캘린더로 돌아와 일정을 수정한다(WF-11).
- 주요 상태: 빈 상태와 오류·거부 메시지는 WF-04와 같다.

### WF-07 캘린더 월·주·일 보기

- 관련: FR-07 / SC-05
- 위치: WF-04 왼쪽, WF-05 본문
- 상단의 (월 | 주 | 일) 버튼으로 바꾼다. 뷰를 바꿔도 보던 날짜를 기준으로 한다(10장 A-4).

월 뷰: WF-04 그림 참고. 한 달을 칸으로 나눠 날짜마다 일정 제목을 표시한다.

주 뷰

```
┌────────────────────────────────────────────────────┐
│ [<] 2026년 9월 2주 [>]   ( 월 | (주) | 일 )        │
├────────────────────────────────────────────────────┤
│        일    월    화    수    목    금    토      │
│         6     7     8     9    10    11    12      │
│ 09:00                                              │
│ 10:00                    [회의 10:00~11:00]        │
│ 11:00                                              │
│ 14:00                    [발표 14:00~15:00]        │
└────────────────────────────────────────────────────┘
```

일 뷰

```
┌────────────────────────────────────────────────────┐
│ [<] 2026년 9월 9일 (수) [>]   ( 월 | 주 | (일) )   │
├────────────────────────────────────────────────────┤
│ 09:00                                              │
│ 10:00  [회의 10:00~11:00]                          │
│ 11:00                                              │
│ 14:00  [발표 14:00~15:00]                          │

```

- 세 뷰 모두 일정을 누르면 팀장은 수정 창(WF-09), 팀원은 조회만 한다.
- 작은 화면에서도 같은 구성이며, 폭에 맞춰 칸을 줄여 그린다.
- 주요 상태: 일정이 없는 기간은 "이 기간에 일정이 없습니다". 삭제된 일정은 나오지 않는다(SC-05 E2).

## 7. 채팅

### WF-08 채팅 영역

- 관련: FR-11, FR-13, FR-15 / SC-09, SC-13
- 위치: WF-04 오른쪽, WF-06 본문
- 구성은 위에서 아래로: 날짜 선택 → 메시지 목록 → 입력창

```
┌──────────────────────────────────────┐
│ 날짜 [ 미결-2 v ]                    │
├──────────────────────────────────────┤
│  김팀원  09-09 10:12                 │
│  내일 회의 몇 시예요?                │
│                                      │
│  홍길동  09-09 10:15                 │
│  오후 2시입니다.                     │
│                                      │
├──────────────────────────────────────┤
│ [_______________________] [ 전송 ]   │
│ [ 변경 요청 ]  (팀원만)              │
└──────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| 날짜 선택 | 날짜를 고르면 그날(한국 표준시 00:00~24:00) 작성된 메시지만 보인다(BR-07). 기본 날짜는 [미결-2] |
| 메시지 목록 | 메시지마다 작성자, 작성 일시, 내용. 일반 메시지와 변경 요청 메시지(WF-10, WF-12)가 함께 나온다. 새 메시지는 자동으로 도착한다(Long Polling) |
| 입력창, 전송 | 일반 메시지를 보낸다 |
| 변경 요청 버튼 | 팀원에게만 표시. 누르면 WF-10 |

- 팀장/팀원 차이: 입력창과 메시지 목록은 같다. [변경 요청] 버튼만 팀원에게 있다.
- 주요 상태

| 상태 | 표시 예시 | 근거 |
|------|-----------|------|
| 선택한 날짜에 메시지 없음 | "이 날짜에 메시지가 없습니다" | SC-13 |
| 오래된 날짜 선택 | 제한 없이 조회된다(무기한 보관) | SC-13, FR-15 |
| 소속되지 않은 팀의 채팅 접근 (서버 거부) | "접근 권한이 없습니다" | SC-09 E1, SC-13 E1 |

### WF-10 일정 변경 요청 보내기 (팀원)

- 관련: FR-12 / SC-10
- 진입: WF-08의 [변경 요청] (팀원만)
- 배치: 채팅 입력창 영역이 변경 요청 입력으로 바뀐다. 넓은 화면과 작은 화면(WF-06)에서 같다.
- 이동: 보내면 채팅 목록에 요청 메시지가 나타난다. [취소]를 누르면 일반 입력창으로 돌아간다(10장 A-5).

```
┌──────────────────────────────────────┐
│ ...  (채팅 메시지 목록)              │
├──────────────────────────────────────┤
│ 변경 요청                            │
│ 대상 일정                            │
│ [ 9/9 14:00 발표 v ]                 │
│   (내가 관련 팀원인 일정만)          │
│ 요청 내용                            │
│ [___________________________]        │
│                                      │
│ [ 취소 ]                   [ 전송 ]  │
└──────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| 대상 일정 선택 | 본인이 관련 팀원으로 등록된 현재 팀의 일정만 나온다(BR-05) |
| 요청 내용 | 바꾸고 싶은 내용을 쓰는 입력창 |
| 전송 | 대상 일정을 참조한 변경 요청 메시지로 저장한다 |

- 팀장/팀원 차이: 팀원만 쓴다. 팀장은 관련 팀원이 될 수 없어 요청을 보낼 수 없고 일정을 직접 수정한다(SC-10 E3).
- 요청에는 처리 상태(대기·완료 등)를 표시하거나 고르는 요소가 없다(BR-06).
- 주요 상태

| 상황 | 표시 예시 | 근거 |
|------|-----------|------|
| 본인이 관련 팀원인 일정이 없음 | 선택 목록에 "요청할 수 있는 일정이 없습니다". 전송 누를 수 없음 | SC-10 E1 |
| 관련 팀원이 아닌 일정·다른 팀 일정으로 요청 (서버 거부) | "이 일정은 변경을 요청할 수 없습니다" | SC-10 E1, E2 |

요청 메시지의 모양 (채팅 목록 안)

```
┌──────────────────────────────────────┐
│  김팀원  09-09 10:20                 │
│  ┌──────────────────────────────┐    │
│  │ 변경 요청                    │    │
│  │ 대상 일정: 발표              │    │
│  │ 9/9 14:00 ~ 15:00   [미결-3] │    │
│  └──────────────────────────────┘    │
│  발표를 4시로 옮겨 주세요.           │
└──────────────────────────────────────┘
```

- 요청 메시지에는 작성자, 작성 일시, 대상 일정(제목, 일시), 요청 내용이 보인다.
- 대상 일정을 요청 당시 내용으로 보일지, 최신 내용으로 보일지는 → [미결-3]

## 8. 일정 화면과 차별점 화면

### WF-09 일정 입력·수정·삭제 (팀장)

- 관련: FR-08, FR-09, FR-10 / SC-06, SC-07, SC-08
- 진입: 캘린더의 [+ 새 일정](추가) 또는 기존 일정 클릭(수정). 팀장만
- 배치: 캘린더 위에 뜨는 창. 넓은 화면에서 채팅은 가려지지 않고 그대로 보인다(SC-07). 작은 화면에서는 캘린더 자리에 창이 열리고, 화면 맨 아래의 [채팅 보기]는 그대로 있다(10장 A-6).
- 이동: 저장, 삭제, 닫기 → 팀 메인

```
┌────────────────────────────────────────┐
│ 일정 수정                     [ 닫기 ] │
├────────────────────────────────────────┤
│ 제목      [______________________]     │
│                                        │
│ 시작      [2026-09-09] [14:00]         │
│ 종료      [2026-09-09] [15:00]         │
│                                        │
│ 관련 팀원 (팀원만 선택 가능)           │
│   [x] 김팀원                           │
│   [ ] 이팀원                           │
│   [ ] 박팀원                           │
│                                        │
│ [ 삭제 ]                   [ 저장 ]    │
└────────────────────────────────────────┘
```

일정 추가는 같은 구성에서 제목이 "일정 추가"이고 [삭제] 버튼이 없다.

| 구성 요소 | 설명 |
|-----------|------|
| 제목 | 텍스트 입력 |
| 시작 / 종료 | 날짜와 시간 |
| 관련 팀원 | 같은 팀의 팀원 역할 구성원 목록에서 고른다. 팀장은 목록에 나오지 않는다(BR-13) |
| 저장 | 추가 또는 수정을 저장한다. 수정하면 최종 수정자와 수정 일시가 기록된다(FR-09) |
| 삭제 | 수정일 때만 표시. 누르면 논리 삭제한다(FR-10) |
| 닫기 | 저장하지 않고 팀 메인으로 돌아간다 |

- 팀장/팀원 차이: 팀장만 이 창을 열 수 있다. 팀원 화면에는 [+ 새 일정] 버튼이 없고 일정을 눌러도 열리지 않는다. 서버도 팀원의 요청을 거부한다.
- 주요 상태

| 상황 | 표시 예시 | 근거 |
|------|-----------|------|
| 종료가 시작보다 앞섬 (같은 것은 허용) | "종료 일시는 시작 일시와 같거나 이후여야 합니다" | SC-06 E1 |
| 관련 팀원에 팀장 지정 (거부) | "팀장은 관련 팀원이 될 수 없습니다" | SC-06 E2 |
| 관련 팀원에 다른 팀 사용자 지정 (거부) | "같은 팀의 팀원만 선택할 수 있습니다" | SC-06 E3 |
| 팀원이 추가·수정·삭제 시도 (서버 거부) | "팀장만 할 수 있습니다" | SC-06 E4, SC-07 E2, SC-08 E1 |
| 팀에 팀원이 없음 | 관련 팀원 목록 자리에 "팀원이 없습니다" | 10장 A-7 |

### WF-11 변경 요청 메시지를 보며 일정 수정 (팀장, 차별점)

- 관련: FR-09, FR-12, FR-14 / SC-11
- 넓은 화면: 채팅의 요청 메시지를 보면서 같은 화면의 캘린더에서 대상 일정을 수정한다. 채팅은 가려지지 않는다.

```
┌─────────────────────────────────────────────────────────────────────────────────────┐
│  Team CalTalk                                                                       │
│  [ 팀 A v ] [미결-1]   초대 코드: AB12CD      [ 알림 ]   홍길동 v  [ 로그아웃 ]     │
├────────────────────────────────────────────┬────────────────────────────────────────┤
│ 캘린더                                     │ 채팅                                   │
│                                            │                                        │
│ ┌──────────────────────────────────────┐   │  김팀원  09-09 10:20                   │
│ │ 일정 수정                 [ 닫기 ]   │   │  ┌──────────────────────────────┐      │
│ │ 제목  [발표______________]           │   │  │ 변경 요청                    │      │
│ │ 시작  [2026-09-09] [16:00] <- 수정   │   │  │ 대상 일정: 발표              │      │
│ │ 종료  [2026-09-09] [17:00] <- 수정   │   │  │ 9/9 14:00 ~ 15:00            │      │
│ │ 관련 팀원  [x] 김팀원  [ ] 이팀원    │   │  └──────────────────────────────┘      │
│ │ [ 삭제 ]              [ 저장 ]       │   │  발표를 4시로 옮겨 주세요.             │
│ └──────────────────────────────────────┘   │                                        │
│   (WF-09 창이 캘린더 위에 뜬다)            │  홍길동  09-09 10:25                   │
│                                            │  알겠습니다. 4시로 바꿀게요.           │
│                                            │ ────────────────────────────────────── │
│                                            │ [___________________________] [ 전송 ] │
├────────────────────────────────────────────┴────────────────────────────────────────┤
│  최근 활동: 10:25 홍길동 - "발표" 일정 수정  |  10:20 김팀원 - 변경 요청 보냄       │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

| 순서 | 동작 |
|------|------|
| 1 | 채팅에서 요청 메시지와 대상 일정을 확인한다 |
| 2 | 필요하면 채팅으로 팀원과 대화한다 |
| 3 | 캘린더에서 대상 일정을 눌러 WF-09로 수정하고 저장한다 |

작은 화면: 채팅과 수정 창을 동시에 놓을 수 없다. [채팅 보기]로 요청을 읽고 [채팅 숨기기]로 돌아와 캘린더에서 일정을 수정한다. 수정 창이 열린 채로 [채팅 보기]를 눌러도 된다.

```
1) 채팅 보임 (요청을 읽는다)       2) 채팅 숨김, 수정 창 열림
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ Team CalTalk     [로그아웃]  │   │ Team CalTalk     [로그아웃]  │
├──────────────────────────────┤   ├──────────────────────────────┤
│ 김팀원 09-09 10:20           │   │ 일정 수정           [ 닫기 ] │
│ ┌────────────────────────┐   │   │ 제목 [발표_____________]     │
│ │ 변경 요청              │   │   │ 시작 [2026-09-09] [16:00]    │
│ │ 대상 일정: 발표        │   │   │ 종료 [2026-09-09] [17:00]    │
│ │ 9/9 14:00 ~ 15:00      │   │   │ 관련 팀원 [x] 김팀원 ...     │
│ └────────────────────────┘   │   │ [ 삭제 ]          [ 저장 ]   │
│ 발표를 4시로 옮겨 주세요.    │   ├──────────────────────────────┤
│ [________________] [ 전송 ]  │   │        [ 채팅 보기 ]         │
├──────────────────────────────┤   └──────────────────────────────┘
│       [ 채팅 숨기기 ]        │
└──────────────────────────────┘
```

- 요청 메시지와 채팅은 저장 후에도 바뀌지 않는다. 일정을 바꾼 근거가 채팅 이력으로 남는다(BR-06).
- 요청 메시지에는 [수락], [거절], [완료] 같은 버튼과 처리 상태가 없다(BR-06). 요청 메시지에서 수정 창을 바로 여는 연결 버튼도 문서에 없어 그리지 않았다.
- 팀장/팀원 차이: 수정은 팀장만 한다. 팀원은 요청 메시지를 봐도 일정을 수정할 수 없다(SC-11 E1). 서버도 거부한다.
- 주요 상태: 수정 검사 오류와 거부 메시지는 WF-09와 같다.

### WF-12 삭제된 일정을 참조한 요청 메시지 (차별점)

- 관련: FR-10, FR-12, FR-13 / SC-12
- 위치: WF-08 메시지 목록(당일 채팅과 일자별 이력 모두)
- 팀장이 대상 일정을 삭제해도 요청 메시지는 지워지지 않고 남는다. 대상 일정 자리에 "삭제됨"이 표시된다.

삭제 전

```
┌──────────────────────────────────────┐
│  김팀원  09-09 10:20                 │
│  ┌──────────────────────────────┐    │
│  │ 변경 요청                    │    │
│  │ 대상 일정: 발표              │    │
│  │ 9/9 14:00 ~ 15:00            │    │
│  └──────────────────────────────┘    │
│  발표를 4시로 옮겨 주세요.           │
└──────────────────────────────────────┘
```

삭제 후

```
┌──────────────────────────────────────┐
│  김팀원  09-09 10:20                 │
│  ┌──────────────────────────────┐    │
│  │ 변경 요청                    │    │
│  │ 대상 일정: 삭제됨  [미결-4]  │    │
│  └──────────────────────────────┘    │
│  발표를 4시로 옮겨 주세요.           │
└──────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|-----------|------|
| 요청 메시지 | 작성자, 작성 일시, 요청 내용은 그대로 보인다 |
| 대상 일정 표시 | "삭제됨"으로 표시한다. 원래 제목도 함께 보일지는 [미결-4] |

- 캘린더(WF-04/05)에는 그 일정이 보이지 않는다.
- 팀장/팀원 차이: 없음. 모든 구성원에게 같게 보인다.
- 삭제된 일정의 요청 메시지에서 할 수 있는 동작(복구 등)은 문서에 없어 그리지 않았다.
