# frontend 작업 규칙

루트 `CLAUDE.md`의 규칙을 먼저 따르고, 아래는 `frontend/` 작업에만 더하는 규칙이다.

## 1. 오버엔지니어링 금지

- 요청받은 것만, 지금 필요한 만큼만 만든다.
- 구현이 하나뿐인 인터페이스, 한 번만 쓰는 추상화, 빈 폴더, 미리 만드는 "유연성"을 두지 않는다 (P1-2).

## 2. 지침에 있는 기능만 구현

- 이슈와 `docs/`에 적힌 기능만 정확히 구현한다.
- 지침 밖의 작업(기능 추가, 주변 코드 "개선", 리팩터링)은 하지 않는다. 필요해 보이면 하지 말고 사용자에게 알린다.

## 3. 기술 스택과 폴더 구조

- `docs/5-project-principle.md`의 프론트엔드 부분(2.2장 레이어, 3.2장 네이밍, 6장 디렉토리 구조)을 따른다.
- 스택: React 19 + TypeScript + Zustand + TanStack Query.
- 서버 데이터는 TanStack Query, 브라우저 상태는 Zustand(`authStore`, `teamStore`)가 맡는다 (F2-3, F2-4).

## 4. 화면

- 스타일(색상, 글자, 버튼, 캘린더 칸, 채팅 영역)은 `docs/APP_STYLE_GUIDE.md`를 따른다.
- 화면 배치는 `docs/4-wireframes.md`를 따른다.

## 5. 백엔드 API

- 백엔드 API 주소는 코드에 직접 쓰지 않고 반드시 환경변수로 쓴다. 읽는 곳은 `src/lib/api.ts` 한 곳이다.
- API 명세는 `docs/swagger.json`을 따른다.
- 환경변수 이름은 빌드 도구 규칙을 따르고, 키 이름만 적은 `.env.example`을 둔다.

## 6. 로그

- 로그는 `src/lib/logger.ts`의 logger 함수로만 남기고, `console`을 직접 쓰지 않는다.
- 개발 환경에서만 출력한다. production에서는 출력하지 않는다.

## 7. SOLID 원칙

- 단일 책임: 컴포넌트는 화면, 훅은 서버 통신·상태, `lib/`는 도구 하나씩만 맡는다.
- 개방·폐쇄: 기존 코드를 고치지 않고 props와 조합으로 확장한다.
- 리스코프 치환: 같은 props 계약을 쓰는 컴포넌트는 서로 바꿔 써도 동작이 같아야 한다.
- 인터페이스 분리: 컴포넌트에는 필요한 props만 넘긴다. 큰 객체를 통째로 넘기지 않는다.
- 의존 역전: 컴포넌트는 fetch를 직접 부르지 않고 훅과 `lib/api.ts`를 거친다.
- 위 원칙은 새 추상화를 만들 근거가 아니다. 1장(오버엔지니어링 금지)이 우선한다.
